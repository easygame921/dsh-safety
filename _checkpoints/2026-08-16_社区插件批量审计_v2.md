## 误报分析与说明

1. **REVIEW ≠ 恶意**：dsh-safety 输出的是"能力证据 + 风险等级"，REVIEW 表示"需要人工复核"，不代表插件是恶意的。本批样本绝大多数是正常社区插件。
2. **常见误报源**：
   - 安全/审计类插件（dsh-plugin-audit 等）：自身代码就是扫描敏感模式，命中 T05/T06 属预期；
   - 带 install 脚本的插件（T03）：多数是资源装配（已白名单降级 harness-pet 等）；
   - 网络能力（T05/T11）：多数是调用 API/遥测，无凭据读取组合时无实害；
   - README 文档里描述危险模式也会命中（如 dsh-plugin-audit 的 README）。
3. **excludeTests 已排除** tests/fixtures 目录（显式恶意样本不参与）。
4. **建议**：将已复核无害的"网络+无敏感读取"类降级为 notice，减少 REVIEW 噪音。
