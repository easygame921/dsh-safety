> 生成时间：2026-08-16

## 已完成

### 1. fs / child_process 真插桩（关键突破）
- 发现：**patch `require('node:fs')` 模块对象后，插件 ESM `import { readFileSync }`
  同样看到新函数**（ESM 命名导入共享 CJS 模块对象）——从"错误即证据"升级为真插桩
- 读 API：记录路径 + 返回空 Buffer；写 API：记录后丢弃；
  readdir/stat/exists：信息性记录；child_process 全部：记录命令 + 模拟空输出
- **路径敏感**：插件根内读取（ESM loader 读源码/入口探测）走真实实现——
  全量 patch 会把插件模块读成空导致 load-failed（实测踩坑）

### 2. 时间加速（timer 插桩）
- setTimeout/setInterval/setImmediate **立即执行回调**（记录原始延迟）
- 延迟触发型恶意（setTimeout 5s 后读凭据）从"完全漏报"→ 全抓到
- 新风险面 `deferred-trigger`（timer + 敏感行为 = 反静态检测手法）

### 3. 工具调用模拟
- ctx.tool 支持三种形态（直接 handler / 链式 register / 无参 tool().register(name,fn)）
- apply 后逐个调用已注册工具 handler（mock 参数）——工具体内夹带行为可暴露

### 4. 事件扩展 + 健壮性
- 事件 3 → 5（+message/create、agent/tool/call）
- 观察窗口 800ms → 2000ms
- `unhandledRejection` 捕获（插件忘 await 的 async 调用不再崩沙箱）

### 5. node_modules 白名单
- 向上查找最近的 node_modules 加入 --allow-fs-read（本地已装依赖插件可加载）

## 踩坑记录（诚实）

1. **全量 patch fs 破坏 ESM loader**：插件模块被读成空 → load-failed →
   路径敏感 patch（插件根内走真实）修复
2. **file:// URL 归一化**：loader 传 file:///D:/... 形式，白名单匹配需剥前缀+去前导斜杠
3. **正则字面量 [\\w.] 坑**：正则字面量里 \\w 是字面反斜杠+w，不是 word 字符类 →
   .env 路径不匹配敏感正则 → 改 [\w.]
4. **benign-lookalike 夹具语法错**：Python 生成器里字符串 "\n 被字面输出 → 修生成器
5. **本地 profiles 插件依赖残缺**：@deepseek-ai/* 未安装 → load-failed 是环境事实
   （非沙箱 bug）；harness-pet（无依赖）completed 验证沙箱正常
